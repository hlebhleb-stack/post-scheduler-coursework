# Проверка API в Postman

Коллекция `coursework.postman_collection.json` содержит 43 запроса и 57 проверок. Запускайте её целиком по порядку. Она создаёт два уникальных тестовых аккаунта и собственные записи, затем удаляет созданные публикации, канал и шаблон. Тестовые аккаунты остаются в БД, поскольку маршрута удаления аккаунта пока нет. Публикации создаются в режиме черновика.

## В приложении Postman

1. Импортируйте коллекцию и одно окружение через Import. `local` предназначено для локального сервера, `render` — для опубликованного приложения.
2. Выберите импортированное окружение. В `telegram_channel` укажите отдельный тестовый канал, в `telegram_bot_token` — токен бота с правом публикации. Секретные значения задавайте локально в Postman. Файлы окружений в репозитории содержат пустые значения.
3. В настройках Postman выберите корень репозитория как рабочую директорию для файлов. Для запроса «Загрузка документа» при необходимости выберите `postman/fixtures/example.txt` вручную.
4. Откройте коллекцию, нажмите Run и выполните все запросы в исходном порядке. JWT и ID создаваемых записей сохраняются скриптами коллекции автоматически.

Импорт окружения `render` сам по себе не выполняет запросы. Прогон на Render обращается к настоящему Telegram при проверке прав канала. Сама коллекция не отправляет сообщения. Не публикуйте экспорт окружения с заполненным токеном бота или токенами сессии.

## Воспроизводимый локальный прогон

```sh
npm ci
TEST_DATABASE_URL='postgresql://user:password@127.0.0.1:5432/coursework_test' npm run test:api
```

Укажите отдельную тестовую PostgreSQL. Запуск применяет миграции, поднимает собственный API на порту 3211, выполняет эту же коллекцию через Newman и останавливает API. При необходимости задайте свободный `API_TEST_PORT`. Настройки рабочего `.env` и облачные секреты не меняются. Для этого прогона используются сгенерированные ключи и тестовый токен. Внешние ответы Telegram подменяются через Node preload исключительно в тестовом процессе; регистрация, JWT, маршруты и PostgreSQL работают без подмены.

В коллекцию входят положительные и отрицательные сценарии регистрации и входа, запрос без JWT и с повреждённым JWT, CRUD шаблонов/каналов/публикаций, изоляция пользователей, ограничения удаления связанного канала, валидация пустого поста и прошедшей даты, форматирование, загрузка и скачивание документа, каскадное удаление вложения.

Для проверки реально истёкшего JWT и фактической отправки медиа требуется отдельный сценарий. Текущая коллекция этого не проверяет.
