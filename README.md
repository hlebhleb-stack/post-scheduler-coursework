# Сервис для планирования публикаций в социальных сетях (постинг по расписанию)

[Рабочий сайт](https://post-scheduler-coursework.onrender.com).

Курсовая работа по ИТИВП. React, Express, Sequelize и PostgreSQL. Публикации, каналы и медиатека доступны после регистрации. Пользователь работает со своими записями. История отправки хранится отдельно от расписания.

## Локальный запуск

Скопируйте `.env.example` в `.env`. Замените пароль PostgreSQL в обеих строках. Сгенерируйте `JWT_SECRET` через `openssl rand -hex 32`, а `CHANNEL_KEY` через `openssl rand -base64 32`. Сохраните ключ шифрования, поскольку он нужен для чтения уже подключённых токенов.

```sh
docker compose up --build
```

Интерфейс будет на http://localhost:3000. PostgreSQL доступна внутри сети Compose. `migrate` создаёт схему после проверки готовности БД. `app` раздаёт собранный React и REST API, `worker` обрабатывает расписание. Остановка стека сохраняет данные в томе `schedule_data`.

При разработке без Docker используйте отдельную PostgreSQL. Задайте переменные из примера в окружении, выполните `npm ci`, `npm run migrate` и `npm start`. Для разработки React запустите `npm run dev` в отдельном терминале. Vite перенаправляет `/api` на локальный Express.

## Telegram

Создайте бота и добавьте его администратором тестового канала с правом публикации. В разделе «Каналы» укажите имя канала или числовой ID и токен бота. Сервер проверит доступ и сохранит токен в зашифрованном виде. Создайте публикацию с текстом, фото, видео MP4, музыкой MP3/M4A, GIF или документом. Редактор поддерживает жирный текст, курсив, подчёркивание, зачёркивание, ссылки, цитаты, моноширинный текст и спойлеры. Можно включить отправку без звука и защиту от пересылки. До 10 вложений общим размером до 50 МБ, фото — до 10 МБ, подпись — до 1024 символов. Альбом содержит фото/видео, только музыку или только документы. GIF отправляется отдельно. Остальные форматы отправляются как документы. Файлы хранятся в PostgreSQL и доступны владельцу публикации. После отправки карточка покажет статус и ID сообщения. Удаление записи из планировщика сохраняет уже отправленное сообщение в соцсети.

## Instagram

Интеграция рассчитана на профессиональный аккаунт и токен Instagram Login с разрешением на публикацию. Укажите поддерживаемую версию в `INSTAGRAM_API_VERSION`, подключите ID аккаунта и токен. Для публикации потребуется доступная Meta HTTPS-ссылка на изображение. Поддерживается одна фотография с подписью. Интеграцию следует проверить с разрешённым тестовым аккаунтом Meta.

## API

`POST /api/auth/register` создаёт аккаунт, `POST /api/auth/login` возвращает JWT. Для `/api/posts`, `/api/channels`, `/api/media` предусмотрены GET списка, POST, а на `/:id` — GET, PUT и DELETE. Для этих маршрутов нужен `Authorization: Bearer …`. Медиатека поддерживает загрузку, список, просмотр, переименование и удаление файлов. Публикация получает самостоятельную копию выбранного файла, поэтому удаление из медиатеки не нарушает расписание. Канал с публикациями можно удалить после переноса или удаления связанных записей.

## Развёртывание

Сайт и API можно развернуть одним Docker Web Service. Укажите отдельную PostgreSQL, `JWT_SECRET`, `CHANNEL_KEY` и `TRUST_PROXY=1` для Render. Команда запуска: `npm run migrate && npm start`. Health check: `/api/health`. Для фоновой задачи используйте тот же `DATABASE_URL` и `CHANNEL_KEY`. Постоянный обработчик запускается через `npm run worker`, периодическая задача — через `npm run worker -- --once`. Облачную публикацию проверяйте на отдельном тестовом канале.

Веб-сервер проверяет очередь каждые пять секунд, пока запущен. Free Render может засыпать при отсутствии запросов; во время сна отправка задерживается до пробуждения. Дополнительно GitHub Actions проверяет расписание примерно раз в пять минут. В этой сессии автоматические schedule-запуски GitHub не наблюдались, поэтому этот резерв нельзя считать гарантией отправки. GitHub может задерживать запуск. Для ручной проверки можно запустить workflow «Проверка расписания» из GitHub. Для локальной демонстрации Compose запускает постоянный обработчик с проверкой через пять секунд при пустой очереди.

## Postman и VS Code

Коллекция API и окружения находятся в `postman/`. Инструкция импорта и локального прогона — в `postman/README.md`. Автоматический запуск коллекции выполняет `npm run test:api` с переменной `TEST_DATABASE_URL`, указывающей на отдельную тестовую PostgreSQL.

Для работы в VS Code откройте корень этого репозитория. В `.vscode/launch.json` настроены запуск сервера с обработчиком и отдельный однократный запуск обработчика. Конфигурации читают локальный `.env`; для запуска вне Docker задайте в нём адрес доступной с компьютера БД. Предварительно выполните `npm run migrate` и `npm run build`. Через Run and Debug можно ставить точки останова в маршрутах API и обработчике.

## Структура приложения и администрирование

Клиент разделён на `pages` (страницы), `components` (общий интерфейс), `context/AuthContext.jsx` (сессия, вход и выход), `services/api.js` (HTTP) и `hooks/useData.js` (загрузка данных). В `server/routes/api.js` собираются маршруты, `controllers` содержит обработчики ресурсов, `middleware` — проверку JWT, прав, входных данных и ошибок. ORM-модель файла медиатеки находится в `server/models`.

Зарегистрируйте аккаунт через сайт. Для назначения роли администратор выполняет в доверенном серверном окружении с доступом к нужной БД команду:

```sh
node --env-file=.env server/scripts/set-role.js user@example.com admin
```

Для снятия роли замените `admin` на `user`. Публичная регистрация всегда создаёт обычного пользователя. После обновления страницы администратору доступен раздел «Администрирование» со сводкой записей, просроченной очереди и ошибок отправки. Проверка прав выполняется по БД при каждом административном запросе. Сводка содержит технические ID, статусы и ошибки, без токенов каналов и содержимого публикаций. Тест `npm run test:api` дополнительно проверяет запрет доступа пользователю, доступ администратора и немедленный отзыв прав со старым JWT.

## Обзор публикаций

После входа открывается `/overview`. Защищённый `GET /api/analytics` возвращает статистику только текущего пользователя. Календарь активности использует дату последней подтверждённой отправки из `deliveries.completed_at` для опубликованного поста; календарные дни считаются в Europe/Minsk. Альбом считается одной публикацией. Общие счётчики и статистика каналов отражают сохранённые записи, удалённые посты в них не учитываются. Просмотры и подписчики соцсетей не собираются.

## Медиатека

В разделе «Медиатека» можно загрузить фото, видео, аудио или документ, посмотреть и скачать файл, переименовать или удалить его. Лимит одной загрузки — 10 файлов общим размером до 50 МБ, фото — до 10 МБ. При создании Telegram-публикации кнопка «Из медиатеки» добавляет выбранные файлы. При сохранении создаются самостоятельные копии вложений, поэтому последующее удаление или переименование файла в медиатеке не меняет уже сохранённую публикацию. Все операции ограничены владельцем.

Три CRUD-модуля приложения — публикации, каналы и медиатека. Модель `server/models/media.js` использует Sequelize. Файлы медиатеки хранятся в таблице `attachments` с `user_id` и пустым `post_id`; копии публикаций привязаны к `post_id`. Старые таблицы существующей БД миграция не удаляет. API шаблонов и подстановка шаблонов из интерфейса убраны.

## YouTube

В Google Cloud включите YouTube Data API v3, настройте External OAuth consent и добавьте Google-аккаунт владельца канала в Test users. Создайте OAuth-клиент Web application с разрешённым URI `https://post-scheduler-coursework.onrender.com/api/youtube/callback`. На сервере задайте YOUTUBE_CLIENT_ID, YOUTUBE_CLIENT_SECRET, YOUTUBE_REDIRECT_URI. Для локальной проверки укажите отдельный localhost callback в Google и в окружении. JSON и секрет не должны попадать в Git. Для отдельного GitHub worker те же ID/secret задаются secrets, URI — repository variable.

Каналы → Подключить канал → YouTube → название → Подключить через Google. Разрешите youtube.upload и youtube.readonly. Refresh token хранится зашифрованным AES-GCM, state действует 10 минут и связан с HttpOnly-cookie. При отозванном доступе используйте «Обновить доступ через Google» в редактировании канала. В режиме Google Testing refresh token обычно истекает через 7 дней; для длительной работы нужен переход из тестового режима с соблюдением требований Google к проверке приложения.

Публикация YouTube содержит название до 100 символов, описание до 5000 символов, одно MP4 до 50 МБ, выбранную аудиторию и доступ private/unlisted/public. По умолчанию — по ссылке. Время означает начало отправки нашим worker, затем YouTube обрабатывает видео. Native publishAt пока не используется. ID в истории означает принятую загрузку, а не завершённую обработку/модерацию. Сетевой сбой после начала загрузки переводит запись в uncertain без автоматического дубля. Бесплатный Render может спать; запуск по расписанию наследует ограничения фонового worker.

Проверки: `node --test test/*.test.js`, `TEST_DATABASE_URL=... npm run test:api`. Внешние Google/YouTube в тестах изолированы. Реальная авторизация и загрузка проверяются владельцем канала отдельно.
