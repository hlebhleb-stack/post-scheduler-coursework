# Сервис для планирования публикаций в социальных сетях (постинг по расписанию)

[Рабочий сайт](https://post-scheduler-coursework.onrender.com).

Курсовая работа по ИТИВП. React, Express, Sequelize и PostgreSQL. Публикации, каналы и шаблоны доступны после регистрации. Пользователь работает со своими записями. История отправки хранится отдельно от расписания.

## Локальный запуск

Скопируйте `.env.example` в `.env`. Замените пароль PostgreSQL в обеих строках. Сгенерируйте `JWT_SECRET` через `openssl rand -hex 32`, а `CHANNEL_KEY` через `openssl rand -base64 32`. Сохраните ключ шифрования, поскольку он нужен для чтения уже подключённых токенов.

```sh
docker compose up --build
```

Интерфейс будет на http://localhost:3000. PostgreSQL доступна внутри сети Compose. `migrate` создаёт схему после проверки готовности БД. `app` раздаёт собранный React и REST API, `worker` обрабатывает расписание. Остановка стека сохраняет данные в томе `schedule_data`.

При разработке без Docker используйте отдельную PostgreSQL. Задайте переменные из примера в окружении, выполните `npm ci`, `npm run migrate` и `npm start`. Для разработки React запустите `npm run dev` в отдельном терминале. Vite перенаправляет `/api` на локальный Express.

## Telegram

Создайте бота и добавьте его администратором тестового канала с правом публикации. В разделе «Каналы» укажите имя канала или числовой ID и токен бота. Сервер проверит доступ и сохранит токен в зашифрованном виде. Создайте публикацию с текстом, фото, видео MP4, музыкой MP3/M4A, GIF или документом. Редактор поддерживает жирный текст, курсив, подчёркивание, зачёркивание, ссылки, цитаты, моноширинный текст и спойлеры. Можно включить отправку без звука и защиту от пересылки. До 10 вложений общим размером до 50 МБ, фото — до 10 МБ, подпись — до 1024 символов. Альбом содержит фото/видео, только музыку или только документы. GIF отправляется отдельно. Остальные форматы отправляются как документы. Файлы хранятся в PostgreSQL и доступны владельцу публикации. После отправки карточка покажет статус и ID сообщения. Удаление записи из планировщика сохраняет уже отправленное сообщение в соцсети.

## Instagram

Интеграция рассчитана на профессиональный аккаунт и токен Instagram Login с разрешением на публикацию. Укажите поддерживаемую версию в `INSTAGRAM_API_VERSION`, подключите ID аккаунта и токен. Для публикации потребуется доступная Meta HTTPS-ссылка на изображение. Поддерживается одна фотография с подписью. Интеграцию следует проверить с разрешённым тестовым аккаунтом Meta.

## API

`POST /api/auth/register` создаёт аккаунт, `POST /api/auth/login` возвращает JWT. Для `/api/posts`, `/api/channels`, `/api/templates` предусмотрены GET списка, POST, а на `/:id` — GET, PUT и DELETE. Для этих маршрутов нужен `Authorization: Bearer …`. Публикация хранит собственную копию текста после подстановки шаблона. Канал с публикациями можно удалить после переноса или удаления связанных записей.

## Развёртывание

Сайт и API можно развернуть одним Docker Web Service. Укажите отдельную PostgreSQL, `JWT_SECRET`, `CHANNEL_KEY` и `TRUST_PROXY=1` для Render. Команда запуска: `npm run migrate && npm start`. Health check: `/api/health`. Для фоновой задачи используйте тот же `DATABASE_URL` и `CHANNEL_KEY`. Постоянный обработчик запускается через `npm run worker`, периодическая задача — через `npm run worker -- --once`. Облачную публикацию проверяйте на отдельном тестовом канале.

Веб-сервер проверяет очередь каждые пять секунд, пока запущен. Free Render может засыпать при отсутствии запросов; во время сна отправка задерживается до пробуждения. Дополнительно GitHub Actions проверяет расписание примерно раз в пять минут. В этой сессии автоматические schedule-запуски GitHub не наблюдались, поэтому этот резерв нельзя считать гарантией отправки. GitHub может задерживать запуск. Для ручной проверки можно запустить workflow «Проверка расписания» из GitHub. Для локальной демонстрации Compose запускает постоянный обработчик с проверкой через пять секунд при пустой очереди.
