# Карта кода курсового проекта

Откройте корень проекта в VS Code или файл `post-scheduler.code-workspace`. Папки сборки `dist` и скачанных библиотек `node_modules` скрыты в проводнике VS Code; файлы остаются на диске. `package-lock.json` вложен под `package.json`.

## Как устроен проект

## В каком порядке разбирать

Не нужно начинать с чтения всего репозитория подряд. Удобнее пройти один запрос целиком, затем добавить следующий сценарий.

1. **Открытие сайта.** `client/main.jsx` → `App.jsx` → `context/AuthContext.jsx` → `components/Layout.jsx`. Где React запускается, что хранится в сессии, какие страницы доступны без входа.
2. **Регистрация и вход.** `pages/Auth.jsx` → `services/api.js` → `server/routes/api.js` → `controllers/auth.js` → `middleware/auth.js`. Пароль, bcrypt-хеш, JWT, передача Authorization, проверка пользователя в БД.
3. **Самый простой CRUD — каналы.** `pages/List.jsx` / `pages/Editor.jsx` → `components/forms/ChannelForm.jsx` → `controllers/channels.js` → `db.js`. Как форма превращается в JSON, SQL и ответ сервера.
4. **Медиатека и ORM.** `pages/MediaLibrary.jsx` → `controllers/media.js` → `models/media.js`. Загрузка multipart, выборка только своих файлов, переименование и удаление.
5. **Публикация.** `components/forms/PostForm.jsx` → `controllers/posts.js` → `schema.sql`. Время, черновик, данные платформы, выбранные файлы и транзакция сохранения.
6. **Реальная отправка.** `worker.js` → `providers/index.js` → `providers/telegram.js` или `providers/youtube.js`. Поиск наступившего задания, блокировка строки, отправка, запись результата. Почему нельзя без проверки повторять неизвестную отправку.
7. **Текст и файлы.** `components/editor` и `server/lib/uploads.js`. Форматирование, безопасный HTML, предпросмотр, ограничения и самостоятельные копии файлов.
8. **Администрирование.** `pages/Admin.jsx` → `controllers/admin/index.js` → нужный ресурс. Сначала список пользователей, затем смена роли, блокировка, расписание и журнал. `helpers.js` содержит общие фильтры, страницы и транзакцию проверки прав.
9. **Обзор.** `pages/Dashboard.jsx` → `controllers/analytics.js`. Счётчики и календарь считаются по фактической подтверждённой отправке.
10. **Запуск и проверки.** Dockerfile, Compose, package.json, Postman и test. Понимать их назначение необходимо, заучивать каждую проверку не требуется.

Первый блок подготовки — запуск, вход/JWT и простой CRUD. Остальные функции разбираются по одной после него. CSS рассматривается отдельно от алгоритмов сервера.

## Что относится к заданию

Обязательный фундамент: React, Express, PostgreSQL, аутентификация, три CRUD-модуля (публикации, каналы, медиатека), ORM-модель, валидация, безопасность, маршрутизация, состояние React, Docker, Git, тестирование и рабочий деплой. Медиатека — третий основной модуль, её удалять нельзя без замены другой полноценной CRUD-сущностью.

Telegram и YouTube реализуют выбранную тему. Календарь активности, форматирование Telegram, предпросмотр вложений и расширенная админ-панель выходят за минимальный набор CRUD, но используются и ранее заказаны владельцем. При этой чистке они сохранены. Удаление работающей дополнительной функции требует отдельного согласования.

JWT, шифрование токенов, проверки владельца, блокировки очереди, обработка uncertain и ограничения файлов — необходимые части надёжной работы, а не неиспользуемый код.

## Что убрано при чистке

- Неиспользуемый пакет шрифта Manrope; интерфейс уже использует системный шрифт.
- Стили удалённых блоков старого обзора, старой админ-панели и поиска медиатеки.
- Декларации CSS, гарантированно перекрытые более поздним безусловным правилом того же селектора. Остальной порядок каскада сохранён.
- SQL-запросы для удалённых блоков каналов и ближайших публикаций в обзоре, а также неиспользуемые счётчики ответа этого API.
- Недостижимая повторная проверка длины подписи Telegram.
- Ветви общего списка для отсутствующего третьего типа ресурса.
- Несуществующая точка входа `main: index.js` в package.json.
- Старые объединённые файлы после переноса функций; пустых совместимых обёрток нет.

SQL-миграции сохранены: они нужны существующей базе Neon. Рабочие таблицы и данные пользователей не удалялись.

## Команды и VS Code

- `npm run format` — привести исходники к единому форматированию.
- `npm run format:check` — проверить форматирование без изменения файлов.
- `npm test` — модульные проверки.
- `TEST_DATABASE_URL=... npm run test:api` — API с отдельной тестовой PostgreSQL, без реальных отправок в соцсети.
- `npm run build` — собрать React.

В меню Terminal → Run Task есть сборка, тесты, проверка форматирования, запуск и остановка Docker + Neon. Рекомендуемый форматировщик — Prettier; это инструмент разработки и в конечный Docker-образ не попадает.

В Run and Debug:

- **API — Neon, без отправки публикаций**: читает `.env.neon`, запускает API на `http://localhost:3001`, не запускает второй обработчик очереди. Общие данные Neon изменяются и на публичном сайте. Google redirect URI для нового подключения из этого адреса нужно настраивать отдельно; уже сохранённые каналы доступны.
- **Обработчик — Neon, реальная отправка, один проход**: выполняет действительно наступившие задания из рабочей базы. Это осознанное действие, не тестовый режим.

`.env`, `.env.neon`, `.env.demo` и Google OAuth JSON содержат секреты. Они не входят в Git. Для проверки API нельзя подставлять рабочую Neon в TEST_DATABASE_URL.

В проект дополнительно установлены навыки Codex ui-skills-root и improve-ui из ibelick/ui-skills. Они находятся в .agents/skills, не импортируются приложением и исключены из Docker build context. Их установка сама по себе не изменяет интерфейс.

## Компоненты Rare UI

В `client/components/ui/` находятся адаптированные компоненты реестра `swamimalode07/rare-ui`: `DurationPicker.jsx`, `DeleteButton.jsx` и `Toast.jsx`. Это визуальные компоненты; запросы к серверу остаются в формах и страницах. Их стили перенесены из Tailwind в общий CSS проекта, подписи переведены на русский, скругления и палитра согласованы с сайтом.

- `PublicationDateTime.jsx` связывает календарную дату с часами и минутами; `PostForm.jsx` переводит выбранное местное время в UTC для API.
- `DeleteButton.jsx` раскрывает подтверждение и ожидает завершения операции. Ошибка API не отображается как успешное удаление.
- `Toast.jsx` отвечает за уведомления; единственный `Toaster` подключён в `main.jsx`, поэтому результат сохранения виден после перехода на другую страницу.
- В `Layout.jsx` одна обводка перемещается между активными пунктами меню; изменение маршрута не пересоздаёт всю рабочую область.

Зависимости этих компонентов: Motion, Sonner, figma-squircle, flubber, react-use-measure и Radix Slot. Tailwind и отдельный UI-фреймворк не добавлялись.
