## Ограничения, которые нельзя выдавать за выполненные проверки

1. Бесплатный Render может засыпать. Cron GitHub задан примерно каждые пять минут, но на момент аудита последние наблюдаемые запуски publish.yml были ручными workflow_dispatch. Точная автономная отправка во время сна Render не доказана. Постоянный локальный worker работает только при включённом компьютере и Docker. Платный постоянно работающий сервер не подключался.
2. Google OAuth остаётся в тестовом режиме. Для длительной работы нужно решить срок жизни доступа, перевод в production и применимые требования Google. При истечении/отзыве доступа есть повторное подключение.
3. Подтверждение пользователя доказывает конкретные реальные отправки Telegram и YouTube. Отдельная реальная проверка всех форматов/альбомов Telegram ещё нужна. Автоматические тесты платформ используют изоляцию внешних API, это явно указано в тестах.
4. Видео YouTube проходит дополнительную обработку/модерацию после принятия загрузки. Native publishAt не используется. При неизвестном результате отправки — uncertain и ручная проверка без автоматического дубля.
5. Не проводился нагрузочный тест на большой аудитории или большой объём файлов. Ограничение приложения — 50 МБ за загрузку; это не обещание поддержки максимальных лимитов соцсетей.
6. Нет независимого подтверждения варианта/официального задания руководителя. Тема зафиксирована со слов владельца.

## Как повторить техническую проверку

```sh
npm ci
npm test
TEST_DATABASE_URL='postgresql://user:password@localhost:5432/coursework_test' npm run test:api
npm run build
```

TEST_DATABASE_URL должна указывать на отдельную тестовую БД, не на рабочую Neon. CI создаёт такую БД автоматически. Тесты очереди не обращаются к настоящим платформам.

На момент аудита: 10 unit-тестов прошли; Postman 43 запроса/57 assertions и семь дополнительных групп API проверок прошли; сборка прошла. npm audit --omit=dev сообщил 0 известных уязвимостей (снимок состояния реестра на дату проверки, не гарантия отсутствия уязвимостей). Реальные облачные учётные записи и права проверены без раскрытия паролей.

## Расширение администрирования

Добавлены списки пользователей, публикаций, каналов, файлов и журнал действий с поиском, фильтрами и пагинацией по 20 строк. Администратор меняет роль, блокирует/разблокирует пользователя, переносит доступные публикации или возвращает их в черновики, удаляет файлы медиатеки без удаления копий в публикациях. Токены и пароли не возвращаются. Изменения записываются в admin_events.

Блокировка проверяется и при входе, и в старом JWT; новые захваты очереди исключают заблокированного владельца. Уже начавшаяся отправка может завершиться. Самоблокировка и снятие собственных прав запрещены, должен оставаться активный администратор. Изменение publishing/published/uncertain через административную форму запрещено. Новая группа API-тестов проверяет права, пагинацию, поиск, блокировку, расписание, защиту неизвестного результата, сохранность копий и журнал.

В колонке платформы используются доступные SVG-значки Telegram/YouTube в скруглённых квадратах. Радиусы небольших элементов и крупных поверхностей вынесены в общие CSS-переменные.
